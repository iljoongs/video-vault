# 속성 관리

> [메인 지시서](../CLAUDE.md)의 하위 문서. 관리 리스트 항목 하나의 상세 속성을 편집하는 `PropertiesWindow`(속성 창)를 다룬다. 항목을 관리 리스트에 추가/제거하는 것 자체는 [동영상 파일 관리](video-file-management.md), 태그/배우/시리즈 마스터 목록 자체의 관리는 각각 [태그 관리](tag-management.md)/[배우 관리](actor-management.md)/[시리즈 관리](series-management.md) 참고. 창을 모덜리스로 띄우는 방식·단일 인스턴스 정책·다른 창과의 실시간 동기화는 [공통 관리](common-management.md)의 "창 관리 정책" 참고.

**관련 파일**: `PropertiesWindow.xaml`/`.xaml.cs`

## 속성 창 (`PropertiesWindow`)

우클릭 메뉴의 "속성", 태그 칩 영역 클릭, 상단 "속성" 버튼으로 열리는 대화상자 (기본 크기 500x1200, 2026-08-02 변경 — 예전 450x1000, 그 전에는 세로 950) — **구현 완료**.

**레이아웃(2026-08-02 변경)**: 창 내용은 `ScrollViewer`로 감싸져 있고, "완전 삭제"/"확인"/"취소" 버튼 줄만 그 밖(창 맨 아래)에 고정되어 있다 — **구현 완료**. 배우를 여러 명 추가해 배우 썸네일 영역이 늘어나는 등 내용이 길어져도 버튼 줄은 항상 보이며, 내용 영역만 세로로 스크롤된다(예전에는 내용이 늘어나면 "확인" 버튼이 창 밖으로 밀려나 보이지 않는 문제가 있었음).

1. 대화상자로 열린다 (모덜리스, `Owner`는 `MainWindow` — [공통 관리](common-management.md)의 "창 관리 정책" 참고).
2. 항목이 가진 파일 정보를 보여준다: 파일명, 크기, 수정일(**크기와 수정일은 같은 줄에 나란히 배치된다**, 2026-08-02 변경 — 예전에는 각각 별도 줄이었음), 전체 경로(읽기 전용 텍스트 상자, 선택/복사 가능), 재생횟수. **파일명은 이름과 확장자가 분리된 두 개의 텍스트 상자로, 같은 줄에 "." 구분자를 사이에 두고 나란히 배치된다**(2026-08-02 변경, **구현 완료** — 예전에는 확장자까지 포함한 파일명 전체가 텍스트 상자 하나였음). 둘 중 하나라도 포커스를 잃으면(`FileNamePart_LostFocus`) 두 값을 합쳐서 기존과 동일하게 rename이 적용된다.
3. **"코드" 입력란이 있다** (2026-08-02 추가, **구현 완료**). `_item.Code`가 비어있으면 창을 열 때 파일명에서 자동으로 제안값을 채운다 — `ManagedVideoItem.DeriveCode(fileName, fullPath)`의 생성 규칙: **① 파일명의 첫 번째 "-" 이전 부분**을 사용하고, **② "-"를 찾지 못하면 폴더명**(`FolderName`과 동일한 규칙, 마지막 폴더 이름 한 단계)을 대신 사용한다. 이미 저장된 코드 값이 있으면 그 값을 그대로 보여준다. 텍스트 상자는 자유롭게 수정 가능하며(**직접 수정 가능**), "확인" 클릭 시 `_item.Code`에 커밋된다("파일 이동" 버튼을 쓰면 그 시점에도 바로 커밋됨). **파일명 텍스트 상자에서 이름을 바꾸면(rename 성공 시) "코드" 입력란도 새 파일명/경로 기준으로 다시 계산되어 반영된다** (2026-08-02 추가, **구현 완료**) — 이때까지 사용자가 입력해둔 코드값은 덮어써진다. **"코드" 입력란 바로 옆(같은 줄)에 "출시일" 입력란이 있다**(`ManagedVideoItem.ReleaseDate`, 2026-08-02 추가, **구현 완료**) — 자유 텍스트 상자로, 자동 제안이나 형식 강제 없이 사용자가 직접 입력한 값을 그대로 저장한다(예: "2023-06-06"). "확인" 클릭 시 `_item.ReleaseDate`에 커밋된다.
4. 태그는 태그 마스터 목록 전체를 체크박스로 나열하고, 체크박스로 여러 개를 동시에 선택/해제할 수 있다 — 태그 마스터 목록 자체의 관리는 [태그 관리](tag-management.md) 참고.
5. 태그 체크박스 목록은 `WrapPanel`로 배치되어 한 줄로 흐르다가 공간이 부족하면 자동으로 다음 줄로 넘어간다.
6. **파일명은 수정 가능한 텍스트 상자(이름/확장자 분리, 위 2번 참고)로 표시된다** (더 이상 "이름 변경" 버튼이 없다 — **구현 완료**). 내용을 바꾸고 포커스를 다른 곳으로 옮기면(`LostFocus`) 두 값을 합쳐 바로 실제 파일이 rename된다(`RenameHelper.TryRenameManagedItemTo`, 대화상자 없이 즉시 적용). 실패(잘못된 파일명, 같은 이름의 파일이 이미 존재 등)하면 텍스트 상자가 원래 파일명/확장자로 되돌아간다. 성공하면 전체 경로/썸네일 미리보기(썸네일 파일도 함께 rename되므로)/품번 표시가 갱신되고, `ActorCreditSync.OnFileRenamed`로 배우 Credits와도 동기화된다(아래 "배우 Credits와의 동기화" 참고, 상세 로직은 [배우 관리](actor-management.md) 참고) — 그 결과로 배우가 자동 추가될 수 있으므로 화면의 배우 선택 상태(`_selectedActors`)도 `SyncSelectedActorsFromItem()`으로 즉시 다시 맞춘다(그렇지 않으면 "확인" 시 오래된 화면 상태로 덮어써서 방금 자동 추가된 배우가 사라짐). `MainWindow`의 F2/우클릭 "이름변경"은 여전히 `RenameWindow` 대화상자를 통해 `RenameHelper.TryRenameManagedItem`을 사용한다(별도 진입점, 내부적으로 같은 `TryRenameManagedItemTo`를 호출하므로 이 경로로 이름을 바꿔도 배우 Credits 동기화는 동일하게 적용된다) — [동영상 파일 관리](video-file-management.md) 참고.
   - **다른 창을 클릭해도 커밋된다(2026-08-04 수정, 구현 완료)**: 파일명 텍스트 상자에서 커서를 유지한 채(같은 창 안의 다른 컨트롤로 옮기지 않고) 다른 최상위 창(예: `MainWindow`)을 클릭하면 이름 변경이 적용되지 않는 버그가 있었다 — WPF의 `LostFocus`는 그 창 자신의 포커스 스코프 안에서의 논리적 포커스 이동에만 반응하는데, 창이 모덜리스로 바뀌면서 사용자가 텍스트 상자 안에 커서를 둔 채로 다른 창을 자유롭게 클릭할 수 있게 됐고, 이 경우 논리적 포커스는 그대로라 `LostFocus`가 발생하지 않았다. `FileNamePart_LostFocus`의 커밋 로직을 `CommitFileNameIfChanged()`로 뽑아내고, `Window.Deactivated`(창이 비활성화될 때 — 실제 키보드 입력이 다른 창으로 넘어가는 시점 기준)에도 같은 메서드를 호출해서 이 경우도 커밋되도록 했다.
7. "전체 경로:" 옆에 버튼이 **세 개** 있다 (2026-08-02 변경 — "파일 이동" 추가) — **구현 완료**. 셋 다 확인/취소와 무관하게 즉시 반영되며, 성공 시 전체 경로/썸네일 미리보기가 모두 갱신된다(썸네일/원본 파일도 함께 이동).
   - **"파일 이동"** (맨 왼쪽, 신규): `MoveByCodeButton_Click` → `RenameHelper.TryMoveToSpecificFolder`. **"코드" 입력란의 값으로 된 폴더**로 파일을 옮긴다 — `RenameHelper.LibraryBasePath`(`E:\happy`, 아래 참고) 바로 밑에 코드 이름의 폴더를 만들고(이미 있으면 그대로 사용) 그 안으로 이동한다(예: `...\0_jp\SSNI-123.mp4`, 코드 `SSNI` → `E:\happy\SSNI\SSNI-123.mp4`). **이동 전에 "이전 위치"와 "이동할 위치"를 모두 보여주는 확인 대화상자**를 띄운다 — **구현 완료**. 대상 폴더가 없으면 자동으로 만든다(`Directory.CreateDirectory`). 이동에 성공하면 그때의 코드 값을 `_item.Code`에도 저장한다.
     - **기준 폴더를 `E:\happy`로 고정**(2026-08-16 변경, 사용자 요청) — 원래는 파일이 지금 있는 폴더의 **바로 위 폴더**를 기준으로 코드 폴더를 만들었는데, 실제 라이브러리는 파일이 여러 단계 깊이 폴더(`0_jp`, `0_Actresses\배우이름`, `fc2` 등)에 들어있는 경우가 많아서 그 규칙대로면 엉뚱한 위치에 코드 폴더가 생기곤 했다(예: `E:\happy\0_Actresses\배우이름\파일.mp4`을 옮기면 `E:\happy\0_Actresses\코드\`에 생겨야 하는데 실제로는 `E:\happy\코드\`에 있길 원함). `RenameHelper.LibraryBasePath = @"E:\happy"` 상수로 고정해서, 파일이 지금 어디에 있든 항상 `E:\happy\{코드}\`로 이동하도록 통일했다 — `ThumbnailHelper.PlaceholderThumbnailDir`와 같은 패턴(이 PC의 실제 라이브러리 경로를 상수로 고정)이다. 실제 항목(3단계 깊이 폴더에 있던 파일, 1단계 깊이 폴더에 있던 파일)으로 검증해 둘 다 정확히 `E:\happy\{코드}\`로 이동함을 확인했다.
   - **"파일 변경"** (예전 이름 "경로 수정"): `RenameHelper.TryEditFullPath`, **파일 대화상자(`SaveFileDialog`)로 새 위치를 선택**한다(폴더/파일명 모두 자유롭게 변경 가능). 대상이 이미 존재하면 대화상자 자체의 덮어쓰기 확인(`OverwritePrompt`)을 거친 뒤, 그 자리에서 직접 `File.Delete`로 지우고 `File.Move`로 옮긴다.
     - **오류 메시지가 실제 원인과 다르게 나오던 버그 수정**(2026-08-16, 사용자 실사용 중 실제 발견 — "'파일 변경'을 하면 중복된 파일이 있다면서 경로를 수정할 수 없다고 나온다") — 예전에는 `File.Move(..., overwrite: true)`의 내장 덮어쓰기 기능에 그대로 맡겼는데, 대상 파일을 다른 프로그램(재생 중인 플레이어 등)이 열어두고 있거나 읽기 전용이면 그 덮어쓰기가 조용히 실패하면서 원본 예외 메시지("지정된 파일이 이미 있으므로 파일을 만들 수 없습니다" 계열)가 그대로 떴다 — 사용자 입장에서는 대화상자에서 이미 "바꾸시겠습니까?"에 예를 눌렀는데도 "파일이 이미 있어서 안 된다"는 것처럼 보여 혼란스러웠다. **수정**: 대상 파일이 있으면 `File.Move`에 맡기지 않고 먼저 직접 `File.Delete`로 지운 뒤(이 단계가 실패하면 "다른 프로그램에서 열어두고 있거나 읽기 전용일 수 있습니다"라는 명확한 원인과 대상 경로를 알려주는 전용 메시지를 띄움) 일반 `File.Move`(덮어쓰기 옵션 없이)로 옮긴다. 실패해도 원본 파일은 그대로 남아있어 데이터 유실은 없다(대상 삭제가 실패하면 이동 자체를 시도하지 않고 그 자리에서 멈춤). 대상 파일이 잠겨있지 않은 정상적인 경우의 덮어쓰기 성공, 그리고 다른 프로세스가 대상 파일을 열어둔 상태에서의 실패(새 메시지로 원인이 명확히 표시되고 원본/대상 파일 모두 그대로 보존됨)를 별도 검증 코드로 확인했다.
     - **"파일 없음" 상태인 항목을 다른 위치의 같은 파일로 재연결하는 기능 추가**(2026-08-16 추가, 사용자 실사용 중 실제 발견 — "dass-870을 다른 위치의 같은 파일로 변경하려는데 안 된다") — 기록된 위치(`item.FullPath`)에 파일이 이미 없는 항목(관리 밖에서 옮겨지거나 지워져 "파일 없음"으로 표시되는 상태, `IsExist = false`)은 옮길 원본 자체가 없는데도 예전에는 무조건 `File.Move`를 시도해 `FileNotFoundException`으로 실패했다. **더 심각한 문제**: 원본이 없다는 걸 확인하기 전에 "대상이 있으면 먼저 지운다" 로직이 먼저 실행돼서, 사용자가 재연결하려고 고른 바로 그 파일을 지워버린 뒤에야 이동이 실패하는 — 재연결하려던 파일까지 잃는 데이터 유실 버그가 될 뻔했다(이번 수정과 함께 발견해 같이 고침). **수정**: `item.FullPath`가 실제로 존재하는지를 가장 먼저 확인해, 없으면 완전히 다른 경로를 탄다 — 사용자가 고른 새 위치에 파일이 있으면(재연결하려는 대상) 아무것도 옮기거나 지우지 않고 `item.FullPath`만 그 위치로 갱신한다(썸네일/원본은 있으면 새 폴더로 따라오도록 `RenameAssociatedFile` 그대로 호출). 새 위치에도 파일이 없으면 "기존 파일과 선택한 파일 모두 존재하지 않습니다"라고 명확히 알린다. 재연결(대상 파일 보존 확인)/양쪽 다 없음, 두 상황과 기존 정상 이동 경로(회귀 없음)를 별도 검증 코드로 확인했다.
   - **"경로 수정"**: `RenameHelper.TryMoveToFolder`, **폴더 선택 대화상자(`OpenFolderDialog`)로 이동할 폴더만 선택**한다 — 파일명은 그대로 유지한 채 폴더만 옮기는 더 단순한 시나리오. 대상 폴더에 같은 이름의 파일이 이미 있으면 실패 메시지를 표시한다.
   - "파일 이동"/"경로 수정" 둘 다 내부적으로 같은 `RenameHelper.TryMoveToSpecificFolder`(폴더로 이동 + `RenameAssociatedFile`로 썸네일/원본 동반 이동 + 대상 폴더 자동 생성)를 공유한다 — "경로 수정"은 대화상자로 고른 폴더를, "파일 이동"은 코드로 계산한 폴더를 넘겨 호출하는 차이만 있다. `RenameHelper` 자체는 [동영상 파일 관리](video-file-management.md)에서 소유하는 유틸리티다. **메인 창 관리 리스트 툴바의 "선택한 파일 이동" 버튼**(2026-08-16 추가)이 이 "파일 이동"과 동일한 대상 폴더 규칙을 여러 항목에 한 번에 적용한다 — [동영상 파일 관리](video-file-management.md) 참고.
8. **재생횟수 입력란은 읽기 전용**이다(`IsReadOnly="True"`, 직접 타이핑으로 수정 불가) — **구현 완료**. 옆의 "초기화" 버튼으로만 0으로 되돌릴 수 있으며, 다른 필드와 마찬가지로 실제 반영은 "확인" 클릭 시 커밋된다. **"재생" 버튼은 "초기화" 버튼 바로 오른쪽, 같은 줄에 있다**(2026-08-02 변경 — 예전에는 아래 별도 줄에 있었음, **구현 완료**) — 클릭하면 창을 닫지 않고도 이 항목의 파일을 바로 재생할 수 있다. `MainWindow`의 재생과 동일하게 재생과 동시에 `PlayCount`가 즉시 1 증가하고(확인/취소와 무관하게 바로 반영, 이름 변경/경로 수정/썸네일 변경과 같은 카테고리), 화면의 재생횟수 입력란도 곧바로 갱신된다. **이 창이 열려 있는 동안 `MainWindow`(관리 리스트)에서 같은 항목을 재생해도 입력란이 그 즉시 따라간다**(2026-08-04 추가, **구현 완료**) — 속성 창이 모덜리스로 바뀌어 열어둔 채로 관리 리스트에서 같은 파일을 더블클릭/재생 버튼으로 재생할 수 있게 됐는데, 예전에는 그 증가분이 입력란에 반영되지 않다가 "확인"을 누르면 `TryCommitFormFields`가 입력란에 남아있던 예전 값을 그대로 다시 써버려서 방금 늘어난 재생횟수가 도로 줄어드는 버그가 있었다. `PropertiesWindow`가 `_item.PropertyChanged`를 구독해(`ItemPropertyChanged`) `PlayCount`가 바뀔 때마다 입력란을 다시 그리는 방식으로 고쳤다 — 이 구독은 `SwitchToItem`으로 다른 항목으로 넘어갈 때 옛 항목에서 새 항목으로 옮겨지고, 창이 닫힐 때 해제된다. **같은 구독으로 썸네일도 따라간다(2026-08-04 추가, 구현 완료)** — `ThumbnailPath`/`ThumbnailOriginalPath`가 바뀌면(예: 이 창을 열어둔 채로 `MainWindow` 아이콘 보기에서 같은 항목의 썸네일을 바꾼 경우) `ItemPropertyChanged`가 `RefreshThumbnailPreview()`를 호출해 썸네일 뷰어도 그 즉시 갱신된다 — 이 창을 닫았다 다시 열어야만 반영되던 문제를 PlayCount와 같은 패턴으로 고쳤다. **시리즈/배우도 같은 구독으로 따라간다**(2026-08-10 추가, **구현 완료**, PlayCount와 동일한 패턴으로 발견·수정된 버그) — "시리즈 동기화"/"배우 동기화" 버튼(관리 리스트 툴바, [배우 관리](actor-management.md)/[시리즈 관리](series-management.md) 참고)처럼 화면(콤보박스/칩)을 거치지 않고 `item.Series`/`item.Actors`를 직접 바꾸는 일괄 작업이 있는데, 이 창을 어떤 항목에 대해 열어둔 채로 그런 작업이 실행되면 `Series`/`Actors`가 바뀌었는데도 화면(시리즈 콤보박스/배우 칩)은 그 변경을 모른 채 예전 상태를 그대로 유지하고 있다가, 다른 항목으로 전환(`SwitchToItem`)되는 순간 `TryCommitFormFields`가 그 예전 상태를 `_item`에 다시 덮어써서 방금 동기화된 값이 초기화되는 버그가 있었다(예: `scop-708`을 선택해 속성 창을 연 채로 "시리즈 동기화"를 실행하면 `item.Series`는 바뀌지만, 다른 항목을 클릭하는 순간 다시 빈 값으로 되돌아감). `ItemPropertyChanged`에 `Series`(`RefreshSeriesComboBox()` 재호출)와 `Actors`(`SyncSelectedActorsFromItem()` 재호출) 케이스를 추가해 해결했다.

    - **콤보박스 드롭다운에도 배우별 썸네일이 함께 표시된다**(2026-08-26 추가, **구현 완료**, 사용자 요청) — 이전에는 `DisplayMemberPath="Name"`이라 이름 텍스트만 나열되어, 이름만으로는 어느 배우인지 헷갈리는 경우(비슷한 이름, 외국어 이름의 로마자 표기 등) 얼굴을 보고 고를 방법이 없었다. `DisplayMemberPath`를 걷어내고 `ItemTemplate`(**72x72** 썸네일 + 이름 — 처음엔 36x36이었으나 같은 날 사용자 요청으로 2배 확대, 아래 선택된 배우 썸네일과 같은 `ThumbnailPathConverter`+`HasThumbnail` 토글 패턴 재사용)을 지정해, 드롭다운을 펼치면 각 항목이 얼굴 썸네일과 함께 나열된다(썸네일 없으면 👤 기본 아이콘, 썸네일 크기에 맞춰 `FontSize`도 18→36으로 함께 키움). `ItemTemplate`을 지정하면 WPF가 접힌 상태의 선택 표시에도 같은 템플릿을 쓰므로, 배우를 고른 뒤 콤보박스 자체에도 그 배우의 썸네일이 보인다. `MaxDropDownHeight`는 `400`(원래) → `600`(2026-08-26, 1.5배로 확대, 사용자 요청)이다. 코드비하인드(`AddActor_Click`이 `ActorComboBox.SelectedItem`을 `ActorItem`으로 읽는 부분, `RefreshActorComboBox`가 `ItemsSource`를 채우는 부분)는 전혀 손대지 않았다 — 화면 표시 방식만 바뀐 것이라 데이터 바인딩 대상(`ActorItem` 객체 자체)은 그대로다.
    - **마우스 휠은 한 번에 항목 하나씩만 스크롤된다**(2026-08-26 추가, **구현 완료**, 사용자 요청) — 항목 높이가 72px로 커진 뒤로 기본 동작(`SystemParameters.WheelScrollLines`, 보통 3줄)대로면 휠 한 번에 여러 항목이 한꺼번에 넘어가 버렸다. `ActorComboBox.DropDownOpened`에서 팝업 내부의 `ScrollViewer`를 찾아(`ActorComboBox.Template.FindName("PART_Popup", ...)` → `Popup.Child`를 루트로 `VisualTreeHelper` 재귀 탐색) `PreviewMouseWheel`을 직접 구독하고, `ScrollViewer.ScrollToVerticalOffset(현재값 ± 항목높이)`로 정확히 한 항목만큼만 옮긴 뒤 `e.Handled = true`로 기본 동작을 막는다. 항목 높이는 `scrollViewer.ExtentHeight / ActorComboBox.Items.Count`로 계산한다(모든 행이 같은 템플릿이라 균일함).
      - **가상화 패널을 쓰면 스크롤할 때 드롭다운이 저절로 닫히는 버그가 있었다** — 처음에는 `ComboBox.ItemsPanel`을 `VirtualizingStackPanel ScrollUnit="Item"`으로 지정하고 `ScrollViewer.LineUp()`/`LineDown()`을 호출했는데(가상화 패널이라 한 번 호출에 정확히 한 항목씩 움직임), 스크롤할 때마다 컨테이너가 재생성되면서 드롭다운이 마우스 캡처를 잃고 저절로 닫혀버리는 버그가 실제로 재현됐다(첫 스크롤은 괜찮다가 다음 스크롤에서 닫히는 등 간헐적이었음). `LineUp`/`LineDown` 대신 `ScrollToVerticalOffset`으로 바꿔도 가상화 패널을 계속 쓰는 한 같은 문제가 남아있어서, 근본 원인이 호출 방식이 아니라 **가상화 자체**(스크롤 중 컨테이너를 계속 새로 만들고 버리는 것)임을 확인했다. 최종적으로 `ItemsPanel`을 가상화하지 않는 평범한 `StackPanel`로 바꿔(컨테이너가 스크롤 중 전혀 재생성되지 않음) 해결했다 — 배우 수가 수백 명 수준이라 비가상화로도 성능 문제는 없다(이 앱의 다른 단순 콤보박스들도 원래 비가상화).
    - **배우 이름/썸네일 클릭 → 배우 관리 창으로 이동** (2026-08-03 추가, **구현 완료**): 배우 칩의 이름 텍스트(`ActorChipName_MouseLeftButtonUp`)나 배우 썸네일(`ActorThumbnail_MouseLeftButtonUp`) 중 아무 곳이나 클릭하면 `ActorManagerWindow`를 열면서 그 배우를 바로 선택하고 스크롤해서 보여준다(`OpenActorManagerFor`). 이를 위해 `ActorManagerWindow` 생성자에 선택 옵션 매개변수 `ActorItem? initialSelection = null`이 추가되었다(지정하면 `ActorsListBox.SelectedItem`으로 즉시 선택하고, `Window.Loaded` 시점에 `ScrollIntoView`). `PropertiesWindow`가 `ActorManagerWindow`를 열려면 배우 마스터 목록뿐 아니라 관리 리스트 컬렉션도 필요해서, `PropertiesWindow` 생성자가 `managedItems`를 새로 받고 `masterActors`/`managedItems` 매개변수 타입도 `ObservableCollection<T>`로 넓어졌다(호출부 `MainWindow.OpenPropertiesWindow`/`ActorManagerWindow.CreditChip_MouseLeftButtonUp` 모두 갱신). 배우 관리 창에서 돌아오면(이름 변경/삭제 등이 있었을 수 있으므로) 배우 콤보박스(`RefreshActorComboBox`)와 선택된 배우 표시(`SyncSelectedActorsFromItem`)를 다시 최신 상태로 맞춘다. → [배우 관리](actor-management.md) 참고.

12. **창 맨 아래 왼쪽에 "완전 삭제" 버튼이 있다** (진한 빨간 글자로 강조) — **구현 완료**. 확인 대화상자를 거친 뒤 이 항목의 관리 데이터를 완전히 삭제한다(관리 리스트에서 완전히 사라지며 `library.json`에 다시 나타나지 않음, [동영상 파일 관리](video-file-management.md)의 "제거(Remove) 메커니즘" — "완전삭제" 참고). 실제 동영상 파일은 삭제하지 않는다. 클릭하면 `PropertiesWindow.PermanentlyDeleted`를 `true`로 설정하고 창을 닫으며, 실제 컬렉션에서의 제거는 호출자인 `MainWindow.OpenPropertiesWindow`가 이 플래그를 보고 수행한다(다이얼로그 자신은 `_managedItems`에 접근할 수 없으므로).
13. **"새 항목" 모드 — 현재 미사용** (2026-08-06 추가, 2026-08-21부터 실제 호출부 없음): 생성자의 `isNewItem` 매개변수(`_isNewItem` 필드)와 아래 설명하는 커밋-시점-지연-추가 로직 자체는 코드에 그대로 남아있지만, **현재 `OpenPropertiesWindow`를 `isNewItem: true`로 호출하는 곳이 코드베이스에 없다** — 유일한 호출부였던 "파일 없이 추가" 버튼이 2026-08-21에 흐름을 바꿔(→ [동영상 파일 관리](video-file-management.md)의 "파일 없이 추가" 항목 참고), 이제 파일명을 먼저 받고 `MainWindow`에서 직접 `_managedItems.Add`까지 마친 뒤에야 이 창을 `isNewItem: false`(기본값)로 연다. 즉 아래 서술은 향후 다른 진입점이 이 모드를 재사용할 경우를 위한 참고용이며, 현재 실행되는 코드 경로는 아니다.
    - 이 모드가 켜지면(생성자에 `isNewItem: true`를 넘기면) `_isNewItem` 필드가 이 항목이 **아직 `_managedItems`에 없는 상태**임을 나타낸다. 이 상태에서 "확인"을 누르거나(또는 버튼을 거치지 않고 닫아도, 규칙은 동일) **파일명을 입력했으면 그 시점(`TryCommitFormFields`)에 `_item.IsValid = false`로 설정한 뒤 `_managedItems.Add(_item)`으로 비로소 관리 리스트에 추가되고 `_isNewItem`이 `false`로 바뀐다. 파일명을 입력하지 않았으면 조용히 추가가 취소된다**(별도 안내 없음). `SwitchToItem`으로 다른(이미 목록에 있는) 항목으로 전환되면 `_isNewItem`도 함께 `false`로 재설정된다.
    - **이미 같은 파일명의 항목이 있으면 막는다**(2026-08-07 추가) — 이미 관리 중인 실제 파일(예: `sdmt-261.mp4`)이 있는 줄 모르고 같은 이름으로 새 항목을 만들면, 서로 다른 두 `ManagedVideoItem`이 같은 `FileName`을 갖게 되는 문제가 있었다(재사용 매칭이 어느 쪽을 골라야 할지 모호해짐 등). 이 검사는 `PropertiesWindow.TryGuardAgainstDuplicateFileName(candidateName)` 공용 헬퍼로 뽑혀 있고 **두 시점 모두에서 호출된다**: ① 새 항목을 처음 커밋할 때(`TryCommitFormFields`, 위에서 설명한 대로 현재는 어떤 호출부도 이 경로를 타지 않는다), ② **커밋된 뒤에도 파일명 텍스트 상자에서 이름을 다시 바꿀 때**(`CommitFileNameIfChanged`의 `IsPlaceholder` 분기 — 처음엔 "sdmt-261"처럼 안 겹치게 만들었다가 나중에 "sdmt-261.mp4"로 고쳐서 겹치게 되는 경우도 있었기 때문에 이 시점도 반드시 막아야 한다. **이 ②는 `IsPlaceholder`만 조건이라 지금도 실제로 쓰인다** — "파일 없이 추가"로 만든 항목의 파일명을 나중에 속성 창에서 다시 바꿀 때). `_managedItems`에 같은 `FileName`(대소문자 구분, 활성/제거 상태 무관, 자기 자신은 제외)을 가진 다른 항목이 있으면 "이미 존재하는 파일명" 경고를 띄우고 **적용을 취소한다**(②는 텍스트 상자를 원래 파일명으로 되돌림) — 사용자가 다른 이름을 입력하거나 "취소"로 빠져나가야 한다. **①과 별개로, "파일 없이 추가"가 처음 항목을 만들 때의 중복 검사는 이제 `MainWindow.AddPlaceholderItem_Click`에 인라인으로 복제되어 있다**(속성 창을 아예 거치지 않으므로 `TryGuardAgainstDuplicateFileName`을 호출할 수 없다) — 로직은 동일(같은 `FileName` Ordinal 비교)하지만 물리적으로 다른 코드다.
    - **제거된 항목으로 취급된다**(2026-08-06 추가, **구현 완료**) — 실제 파일이 없으므로 추가되는 즉시 `IsValid = false`로 설정해 일반 "제거"와 동일하게 처리한다: 기본 목록에는 보이지 않고 "제거된 항목도 표시" 체크박스로만 보이며(회색으로 표시), `library.json`에 다른 항목과 함께 저장된다(`IsExist`는 애초에 `false`). 나중에 같은 이름의 실제 파일이 추가되면 아래 "재사용" 매칭으로 데이터를 그대로 이어받는다 — [동영상 파일 관리](video-file-management.md)의 "제거(Remove) 메커니즘" 참고.
    - `RefreshFileOperationAvailability()`가 `_item.IsPlaceholder`(실제 파일이 있어야 동작하는 재생/파일 변경/경로 수정/파일 이동 버튼을 비활성화하고 툴팁으로 "실제 파일이 없는 항목입니다."를 보여줌)와 `_isNewItem`("완전 삭제" 버튼 비활성화 — 아직 지울 대상이 없으므로)에 따라 버튼 활성/비활성을 갱신하며, 새 항목 생성 시점과 `SwitchToItem` 양쪽에서 다시 호출된다. **썸네일 추가/삭제 버튼은 비활성화하지 않는다** — 아래 참고.
    - 파일명 텍스트 상자의 커밋(`CommitFileNameIfChanged`)도 `IsPlaceholder`일 때는 `RenameHelper`(`File.Move`)를 거치지 않고 `_item.FileName`/`FullPath` 값만 직접 갱신한다 — 이동/이름 변경할 실제 파일이 없기 때문이다. 코드/출시일/메모/태그/배우는 일반 항목과 동일하게 편집 가능하다.
    - **썸네일은 실제 파일이 없어도 지정할 수 있다**(2026-08-06 추가, **구현 완료**) — `PropertiesWindow.ApplyThumbnail`/`MainWindow.ApplyThumbnail`(아이콘 보기 클릭·드래그 앤 드롭 공용) 모두 `item.IsPlaceholder`면 `ThumbnailHelper.CreatePlaceholderThumbnail`을 사용한다. 일반 항목의 `CreateThumbnail`은 "동영상 파일과 같은 폴더"에 저장하는데, 플레이스홀더는 실제 폴더가 없으므로(`FullPath`가 파일명뿐) 대신 고정 폴더 `ThumbnailHelper.PlaceholderThumbnailDir`(`E:\happy\thumbnail`)에 `{파일명}.thumbnail.jpg`/`{파일명}.original{확장자}`로 저장한다. **이전에는 이 분기가 없어 `Path.GetDirectoryName("파일명뿐인 경로")`가 빈 문자열을 반환해도 예외가 나지 않아, 앱의 실행 폴더(작업 디렉터리) 기준 상대 경로에 조용히 썸네일 파일이 생기는 버그가 있었다** — 고정 폴더 분기로 해결.
    - **재생 시도 시 친절한 안내로 대체된다**(2026-08-06 추가, **구현 완료**) — `MainWindow.PlayManagedItem`이 `item.IsPlaceholder`면 `Process.Start`를 시도하지 않고 "실제 파일이 없는 항목입니다." 안내만 표시한다(더블클릭 재생/재생 버튼/우클릭 메뉴 모두 이 메서드를 공유하므로 전부 적용됨). `PropertiesWindow`의 "재생" 버튼은 위와 같이 아예 비활성화된다.

## 배우 Credits와의 동기화 (요약 — 상세는 [배우 관리](actor-management.md))

(2026-08-02 추가, **구현 완료**): 이 항목의 `Actors`와 배우 마스터 목록의 `Credits`가 어긋나지 않도록 `ActorCreditSync`가 두 방향으로 동기화한다.
- 배우 칩을 ✕로 제거하고 "확인"으로 커밋하면, 그 배우의 Credits에서도 이 파일의 품번을 제거한다(`TryCommitFormFields`가 커밋 직전에 `_item.Actors`와 화면에 남은 선택을 비교해 빠진 배우를 찾아 `ActorCreditSync.OnActorRemovedFromItem`을 호출).
- 파일명이 바뀌면(위 6번) `ActorCreditSync.OnFileRenamed`가 실행된다.

시리즈 콤보박스도 같은 방식으로 [시리즈 관리](series-management.md)의 `SeriesCreditSync`와 연동된다 — "배우" 항목 바로 밑에 있으며, 마스터 목록 이름 + 맨 앞의 "(없음)" 항목(시리즈 미지정을 나타내는 센티널, `PropertiesWindow.NoSeriesLabel`)으로 채워지고, "확인" 클릭 시 선택값이 "(없음)"이면 `_item.Series`를 빈 문자열로, 아니면 선택된 이름으로 설정한다. 마스터 목록에서 이미 삭제된 시리즈 이름을 항목이 그대로 갖고 있으면(다른 곳에서 삭제된 경우) 목록에 함께 포함시켜 데이터가 조용히 사라지지 않게 한다(`RefreshSeriesComboBox`).

"확인"을 누르면 재생횟수 입력란의 값, 코드, 메모, 선택된 태그/배우/시리즈가 항목에 반영되고(배우/시리즈 Credits 동기화도 이 시점에 함께 적용됨), "취소"를 누르면 그 변경 사항만 버려진다(파일명 변경/경로 수정/파일 이동/썸네일 추가·삭제/완전 삭제/재생(재생횟수 증가 포함)은 이미 실제로 적용된 상태라 취소로 되돌아가지 않는다. "파일 이동"으로 성공한 경우의 코드 값도 이미 즉시 반영되어 있다).

## 이 영역의 컨벤션

- **엔터 키로 버튼이 눌리지 않는다** (2026-08-02 변경, **구현 완료**) — "확인" 버튼의 `IsDefault="True"`를 제거했다. 예전에는 파일명/코드 같은 한 줄 텍스트 상자에서 Enter를 치면(줄바꿈을 직접 처리하는 메모 상자 제외) 의도치 않게 "확인"이 눌렸다.
- **창을 닫기(제목 표시줄의 X, Alt+F4 등) 버튼으로 닫아도 변경사항이 저장된다** (2026-08-02 추가, **구현 완료**) — `Window.Closing` 이벤트(`Window_Closing`)에서 `DialogResult`(모덜리스 전환에 따른 대체 방식은 [공통 관리](common-management.md)의 "창 관리 정책" 참고)가 아직 설정되지 않은 경우(= "확인"/"취소"/"완전 삭제" 버튼을 거치지 않고 닫힌 경우)에만 "확인"과 동일한 커밋 로직(`TryCommitFormFields`, `Ok_Click`과 공유)을 실행하고 닫기를 완료로 표시한다. 재생횟수 값이 올바르지 않는 등 검증에 실패하면 `e.Cancel = true`로 닫기 자체를 막는다(확인 버튼과 동일한 검증 규칙). "취소"/"완전 삭제" 버튼은 클릭 시 이미 종료 처리를 해두므로 이 로직을 건너뛰어 기존 동작(변경사항 버림/완전 삭제)을 그대로 유지한다.
- 관리 리스트의 데이터 모델(JSON 직렬화 대상)에 `private set`(또는 setter 없음)을 쓸 때는 반드시 `[JsonInclude]`를 붙인다 — 전역 규칙은 [공통 관리](common-management.md)의 컨벤션 참고.
